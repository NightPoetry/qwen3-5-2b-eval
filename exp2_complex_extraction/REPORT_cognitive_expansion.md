# 认知递归展开实验报告

## 实验背景

Qwen3.5-2B 模型在工具增强文本提取任务中，需要同时完成：循环导航、条件判断、结果记录。
诊断发现模型是"单线程"的——能力叠加导致崩溃。

## 诊断数据

### 单项能力测试

| 能力 | 测试 | 通过率 | 备注 |
|------|------|--------|------|
| 纯循环 (read->advance) | 3 seeds | **100%** (3/3) | 包括之前失败的 seed 1, 7 |
| 条件判断 (多行静态) | 6 种 prompt | **0%** (0/6) | 完全无法区分缩进 |
| 条件判断 (单行) | 10 行 | **80%** (8/10) | 漏看前导空格、下划线名称拆分 |
| 条件判断 (3行批次) | 3 批 | **100%** (3/3) | 对比上下文帮助判断 |
| 条件判断 (read_next JSON 格式) | 1 批 | **100%** (1/1) | 工具返回格式天然辅助判断 |

### 组合能力测试

| 方案 | seed=42 | seed=1 | seed=7 | 问题 |
|------|---------|--------|--------|------|
| 原版 prompt (15行步骤) | F1=1.00 | F1=1.00 | F1=0.80 | seed7 STOP×7 |
| 极简 prompt (3句话) | F1=0.00 | F1=0.00 | F1=0.00 | 完美循环但 0 record |
| 自动标注 (★目标) | F1=0.00 | F1=0.67 | F1=0.73 | 乱记录，不理解标记 |
| **认知展开** | **F1=1.00** | **F1=0.57** | **F1=0.75** | 展开判断OK，record 漏调 |

### 认知展开器单独测试

将"是否顶级函数"拆解为 2-4 个微型隔离子问题：

```
子问题1: "这行第一个字符是什么？" → 单字符回答
子问题2: "字符X是空格吗？" → YES/NO
子问题3: "这行以 'def ' 开头吗？" → YES/NO
子问题4: "这是函数定义，函数名是？" → 名称
```

**准确率: 8/8 (100%)** — 对比直接判断的 0/6

关键发现：子问题1（首字符检测）对缩进行返回 'd' 而非空格（模型看不到 backtick 内的前导空格），
但子问题3 能正确补偿——问"是否以 def 开头"时，缩进行被正确拒绝。**多步自我修正。**

## 核心发现

### 1. 2B 模型是单线程处理器

- 给一个任务 → 做得很好
- 给两个任务 → 有时做好一个
- 给三个任务 → 崩溃
- 极端：给"循环+判断+记录"→ 只做循环，完全不记录

### 2. 认知展开将复杂判断转化为原子操作

- 直接问"是否顶级函数"→ 0% 准确率（6种prompt全败）
- 拆成微型子问题（是/否、单字符） → 100% 准确率
- 每个子问题在隔离上下文中执行（独立 API 调用，不共享对话历史）

### 3. 多步自我修正

展开器的子步骤有冗余：即使步骤1答错（首字符误判），步骤3能独立得出正确结论。
这类似于冗余检查系统——单点故障不导致整体失败。

### 4. 剩余问题：record 漏调

展开器 100% 准确，但主循环模型不总是根据"发现目标"指示调用 record()。
seed=42 全部正确(5/5)，seed=1 只记录 2/5，seed=7 记录 3/5。
推测：模型在对话早期专注建立循环模式，后期才开始响应 record 指示。

## 后续方向

1. **修复 record 漏调**：在发现目标时注入更强的 user message，或将 record 也自动化
2. **修复缩进误报**：改进子问题措辞，解决 backtick 内前导空格不可见问题
3. **扩展到其他任务**：HTML 标题、压缩代码的展开器
4. **性能评估**：当前每行含 def 的代码需 3-4 次额外 API 调用，考虑成本/准确率平衡
5. **对比实验**：在相同条件下对比原版 B、认知展开、自动标注的完整 27-case 矩阵

## 技术架构

```
主循环（模型对话 #1）          展开子问题（隔离对话 #2..#N）
  │                              │
  ├─ read_next()                 │
  │    ↓                         │
  │  [Runner 拦截]               │
  │    │                         │
  │    ├─ 行含 "def"?  ──yes──→  ├─ "首字符是?" → 'd'
  │    │                         ├─ "'d'是空格?" → NO
  │    │                         ├─ "以'def '开头?" → YES
  │    │                         ├─ "函数名是?" → 'foo'
  │    │                         └─ 返回: {is_target:true, item:'foo'}
  │    │                         │
  │    ├─ 注入到 read_next 结果  │
  │    ↓                         │
  │  模型看到"发现目标: foo"      │
  │  → record(item='foo')        │
  │  → advance_past()            │
  │  → 循环继续                   │
```
