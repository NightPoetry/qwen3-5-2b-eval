# 可执行知识网络：从被动数据到主动程序

## 摘要

本文报告一种面向极小语言模型（2B参数）的知识组织方法。与传统知识图谱（Knowledge Graph）将知识表示为声明性三元组不同，本方法将知识表示为**带操作语义的可执行节点图**。每个节点包含触发条件、执行步骤序列和有向引用边；边的遍历受触发门控约束。该结构天然具备顺序、选择、循环三种程序结构，构成图灵完备的控制流等价物。

实验表明，在 Qwen3.5-2B 模型上，传统 KG + 模型推理方案无法产出可用代码（模型无法从事实推导行动），而本方法通过系统编排达成 100% 稳定的代码生成。

---

## 1. 问题

2B 参数模型的认知极限已被实验确认：
- 单任务能力：循环导航 100%、语义提取 100%
- 组合能力：循环 + 判断 → 崩溃（只做循环不做判断）
- 推理能力：给定事实推导行动 → 0%（6种prompt全败）

传统知识图谱要求消费者具备**检索→推理→执行**的完整链路。2B 模型在每一环都失败。

需要一种知识组织方式，使得**系统本身承担检索、推理、执行，模型仅在隔离上下文中回答原子问题**。

---

## 2. 传统知识图谱的局限

### 2.1 结构

```
节点: 实体/概念
边:   类型化关系 (causes, prevents, is-a, part-of)
内容: 声明性事实
```

### 2.2 消费模式

```
查询图 → LLM 阅读相关子图 → LLM 推理行动 → LLM 生成代码
```

全部认知负载在 LLM 侧。对 GPT-4 级别模型可行，对 2B 不可行。

### 2.3 核心缺陷

| 缺陷 | 原因 |
|------|------|
| 无操作语义 | 节点是事实不是程序，"知道"不等于"能做" |
| 无触发条件 | 所有知识对所有上下文同等可见，增加选择压力 |
| 无执行路径 | 从事实到行动需要推理，推理是2B做不到的 |
| 无门控遍历 | 边是静态关系，不能按内容动态可见/不可见 |

## 3. 可执行知识网络

### 3.1 节点结构

```json
{
  "id": "001",
  "name": "flex子元素防溢出",
  "trigger": {
    "type": "regex",
    "pattern": "flex:\\s*1(?!.*min-width)"
  },
  "steps": [
    {"actor": "system", "action": "regex_find", ...},
    {"actor": "system", "action": "check_property", ...},
    {"actor": "system", "action": "inject", ...}
  ],
  "refs": ["010"]
}
```

每个节点是一个**有前置条件的过程**（guarded procedure），不是一个事实。

### 3.2 边语义

```
refs: ["010"]  →  当且仅当 010 的 trigger 被当前内容满足时，边可遍历
```

边不是"A与B有关系"，而是"从A出发，如果条件满足，可以跳转到B执行"。

### 3.3 遍历 = 执行

传统KG：遍历图是**检索信息**的过程。
本系统：遍历图是**执行程序**的过程。到达一个节点 = 执行该节点的 steps。

### 3.4 程序结构完备性

| 结构化编程要素 | 对应实现 |
|---------------|---------|
| 顺序 (sequence) | 节点内 steps 序列 |
| 选择 (selection) | trigger 条件门控 |
| 循环 (iteration) | 环状 refs + 触发门控 |

三要素齐备 → 结构化程序等价物。

---

## 4. 对比总结

| 维度 | 传统知识图谱 | 可执行知识网络 |
|------|-------------|---------------|
| 节点本质 | 常量（事实） | 函数（过程） |
| 边本质 | 静态关系 | 门控跳转 |
| 遍历含义 | 检索 | 执行 |
| 决策者 | 消费方（LLM） | 图本身（trigger） |
| 对LLM要求 | 检索+推理+执行 | 仅回答原子问题 |
| 适用模型 | ≥70B | ≥2B |
| 可见性控制 | 全局可见 | 邻接可见（减少选择压力） |
| 循环能力 | 无（纯数据无控制流） | 有（refs环 = 迭代精化） |

## 5. 代码类比

```python
# 传统KG = 数据库，需要聪明的消费者
kg = {"flex:1": {"causes": "overflow"}, "min-width:0": {"prevents": "overflow"}}
# 2B模型读了这个什么也做不了

# 可执行知识网络 = 函数图，系统直接执行
def card_001(content):
    if re.search(r"flex:\s*1", content):     # trigger（选择）
        blocks = find_flex_blocks(content)    # step1（顺序）
        for b in blocks:
            if "min-width" not in b:          # step2（顺序）
                inject(b, "min-width:0")      # step3（顺序）
        if triggered(card_010, content):      # ref边（门控跳转）
            card_010(content)                 # 到达 = 执行
```

## 6. 实验验证

### 6.1 代码生成管线

任务：从一句话需求生成完整 Web 应用（HTML + CSS + JS）。

| 方案 | 结果 |
|------|------|
| 直接生成（2B一次性输出全部） | 不可用（HTML/JS混合，ID不一致） |
| KG辅助（给模型看知识图谱再生成） | 不可用（模型无法从事实推导步骤） |
| 可执行知识网络（系统编排+知识卡验证） | **3/3 稳定通过** |

### 6.2 知识路由效果

| 阶段 | 总卡数 | 可见卡数 | 触发卡数 |
|------|--------|----------|----------|
| CSS生成 | 12 | 5 | 2（flex+间距） |
| JS生成 | 12 | 3 | 1（confirm） |
| Phase0后 | 12 | 2 | 2（最少决定+状态） |

不相关知识对模型完全不可见——**零选择压力**。

---

## 7. 结论

可执行知识网络不是知识图谱的改良版——它是一种本质不同的结构：

1. 从**数据**变为**代码**
2. 从**需要智能消费者**变为**自身携带执行能力**
3. 从**全局可见**变为**邻接可见+触发门控**
4. 从**无控制流**变为**完备程序结构**

这使得 2B 参数的极小模型也能完成复杂任务——因为复杂性不在模型里，在图里。
