## 一、项目概况

**定位**: 让 Qwen3.5-2B 通过可执行节点图完成复杂任务。

**核心发现**: 知识不应该是被动数据（传统KG），应该是主动程序（可执行节点）。节点 = 函数，边 = 门控跳转，遍历 = 执行。

**技术栈**: Python + Qwen3.5-2B (LM Studio) + 栈展开引擎

**模型服务**: `http://localhost:1234/v1/chat/completions`，模型名 `qwen3.5-2b`

## 三、架构总览

### 引擎（engine.py，~120行，唯一写死的代码）

```
用户说一句话
    │
    ▼
万能入口(000) — 连接所有顶层节点
    │
    ▼
各节点检查自己的trigger
    │ 满足的激活
    ▼
执行节点代码 → context更新
    │
    ▼
检查邻接(refs)的trigger
    │ 满足的压入栈
    ▼
栈顶弹出，重复
    │ 栈空
    ▼
停机 → 记录光标位置（最后激活的节点）
    │
    ▼
下一轮从光标的邻接开始（不回入口）
    │ 邻接不匹配
    ▼
回退到000（话题切换）
```

### 节点结构

```python
Node(
    id="001",                              # 唯一标识
    name="flex防溢出",                      # 人读名称
    trigger={"type": "regex",              # 触发条件
             "pattern": "flex:\\s*1"},
    execute=execute_fn,                     # fn(ctx) -> ctx
    refs=["010"],                          # 邻接节点
    metadata={"source": "...",             # 来源
              "category": "..."},          # 类别
)
```

### 三个关键创新

| 创新 | 内容 |
|------|------|
| **可执行节点** | 节点是函数不是常量，到达即执行 |
| **光标上下文** | 停机位置=记忆，图=大脑，不是状态机 |
| **自举预设** | 用户保存=创建新节点，系统在运行中增长 |

## 五、与传统KG的本质区别

| 维度 | 传统KG | 可执行知识网络 |
|------|--------|---------------|
| 节点本质 | 常量（事实） | 函数（过程） |
| 边本质 | 静态关系 | 门控跳转（trigger满足才可遍历） |
| 遍历含义 | 检索 | 执行 |
| 决策者 | 消费方（LLM） | 图本身（trigger） |
| 对LLM要求 | 检索+推理+执行 | 仅回答原子问题 |
| 循环能力 | 无（纯数据） | 有（refs环=迭代精化=图灵完备） |
| 上下文 | 外部维护 | 图中的位置 |

## 六、演进历史（v0.1 → v2）

```
v0.1  线性管线（Phase 0→1→2→3→4），硬编码
  │
  │  问题：事件层不稳定，ID不一致
  ▼
v1    事件模板化 + ID验证 + 知识卡
  │
  │  问题：知识全可见增加选择压力
  ▼
v1.5  网状路由（邻接可见+触发门控）
  │
  │  问题：管线还是写死的
  ▼
v2    节点引擎（栈展开，~120行引擎，所有逻辑在节点中）
  │
  │  问题：模板是死的
  ▼
v2.1  碎片节点（HTML/CSS各段独立节点）
  │
  │  问题：用户不能自定义
  ▼
v2.2  自举预设（用户保存=创建新节点）
  │
  │  问题：每次从000重进=状态机
  ▼
v2.3  光标上下文（停机位置=记忆，续入不回入口）
  │
  │  问题：入口手动选路径
  ▼
v2.4  万能入口（所有任务走000，trigger自己筛选）+ 内容创作节点
```

## 十、核心哲学

2B模型是单线程处理器。给它一件简单的事，它做得完美。给它两件事，它就崩。

所以：
- 复杂性不在模型里，在图里
- 模型做不到100%的事交给确定性代码
- 知识是节点不是描述——到达即执行
- 上下文是位置不是状态——停在哪就从哪继续
- 用户保存=创建节点——系统在运行中增长
- 环=迭代精化——图灵完备的组成部分

引擎只有~120行。所有智能在90个节点里。
