## 一、架构变更：聊天记录与工作记忆分离

### 核心设计

**之前**: `_chat_history` 随 context 每轮传递，所有聊天节点都能看到完整历史。2B 拿到完整上下文后自己就能理解——网络路由沦为摆设。

**之后**: 三层分离。

```
聊天记录 ──→ 文件存储 (chat_logs/{session_id}.json)
                ↑
            回忆节点 880（按需检索）
                ↑
           "记得/之前/上次/说过..."

工作记忆 ──→ context dict（节点执行产生的状态）
             _domain_routed, _chat_response, _recalled...
             与聊天记录完全无关

光标 ──→ context._cursor（位置记忆）
         编码了"我们在聊什么"，不需要聊天记录重复
```

### 新增节点

**880 回忆检索** (`nodes/880_chat_recall.py`):
- 触发词: 记得/之前/刚才/上次/回忆/你说过/忘了/忘记/提过/说过
- 机制: 分块(4条/块) → 关键词提取 → 命中评分 → top-2 注入工作记忆 → LLM 生成回复
- 参考: HelloWorldStoryEngine 渐进式扫描 + GrowBox 两级索引

### 修改的节点 (7个)

全部移除 `_chat_history` 依赖：
- 890 兜底对话 — 用 `_turns` 判断是否在对话中，用光标提示上下文方向
- 870 自我袒露 — 只凭 task 直接回复
- 860 感谢赞美 — 只凭 task
- 800 打招呼 — 只凭 task
- 810 情感表达 — 只凭 task
- 820 寻求安慰 — 只凭 task
- 830 情绪发泄 — 只凭 task
- 840 哲学存在 — 只凭 task
- 850 试探玩闹 — 只凭 task

### 修改的文件

**app.py**:
- 移除 `_chat_history` 传入 context
- chat log 存文件 `chat_logs/{session_id}.json`（最近 100 条）
- 传入 `_chat_log_path` 供回忆节点使用

## 二、3D 可视化增强

### 大脑布局

`forceLayout` → `brainLayout`：
- 左右半球结构：左脑（工程/推理/方法论，x<0）右脑（对话/创作/情感，x>0）
- 域抽象节点：中心环上方
- 输出节点：中心环下方
- 000 入口：原点
- 80 轮轻柔力迭代分离邻近节点

### 流星/水滴拖尾

光束头从 3 层升级为 3+1 层：核心 + 光晕 + 外层辉光 + **8个拖尾小球串**

```
  ●  ← 亮色核心 (0.35)
 ●●  ← 光晕 (0.8)
◉◉◉  ← 外层辉光 (1.6)
○●○●○●○●○  ← 水滴拖尾 (8个小球，渐小渐暗)
────────────  ← 发光连线
```

- 拖尾小球链：每帧更新位置（链式传递），到达后渐隐缩小
- 波束头更大 (core 0.45, halo 1.1, outer 2.4)
- 拖尾更长 (10个球 vs 8个)
- 速度更慢 (min 0.55s vs 0.3s)

### 暗线连接

- 边线基础透明度从 0.10 → 0.18
- 边线颜色从 0x060e1e → 0x0e1a2e（更亮）
- 未激活时也能看到网状结构
